# AI 인물 생성과 내 인물 목록

인물 생성은 카페 사진에 등장시킬 재사용 인물 소재를 만든다. 단순한 밝은
배경에 인물 한 명의 얼굴·머리·옷·자세를 선명하게 표현하며, 카페 배경이나
커피 제품은 생성 단계에서 만들지 않는다. 기본 손은 빈 상태다.

## 사용자 흐름

1. AI와 수정하기 → 인물 생성에서 인물의 외형과 자세를 설명한다.
2. 생성 결과를 계정의 내 인물 목록에 자동 저장한다. 저장 실패 시 결과를
   유지하고 저장만 다시 시도한다. AI를 다시 호출하지 않는다.
3. 목록에서 썸네일을 확인하고 이름 변경·삭제·이 인물 사용을 선택한다.
4. 이 인물 사용은 AI 사진 수정 탭에 인물 참고 사진을 추가한다.
   현재 카드의 카페·커피 사진이 항상 수정 원본이다.
5. 사용자가 배치·동작·제품 등에 대한 수정 요청을 보내고 결과를 확인한다.
   이 사진 적용을 눌렀을 때만 카드 사진을 바꾸고 자동 저장한다.

인물은 다른 카드나 이후 작업에서도 다시 선택할 수 있다. 생성한 인물을
사용할 때 기존 카드 사진을 인물 원본으로 교체하지 않는다. 참고 이미지
한도는 총 3장으로 유지하며, 인물을 선택해도 기존 참고 사진을 임의로 지우지 않는다.

## 저장과 접근

인물 목록은 계정별 데이터와 비공개 이미지 저장소에 저장한다. 다른 계정은
목록·원본 이미지에 접근할 수 없으며, 목록 조회 시 제한 시간의 서명 URL을 쓴다.
생성·저장·이름 변경·삭제는 로그인한 계정만 가능하다. 로컬 구성은 계정별
브라우저 저장소를 사용하며 클라우드 저장 실패를 로컬 성공으로 표시하지 않는다.

## 생성 및 수정 계약

- POST /generate-person은 기존 Cloudflare Worker, Supabase 인증 및 공유 이미지 횟수를 사용한다.
- GPT Image 2, 1024×1024, medium, JPEG, 1장 설정을 유지한다.
- 인물 생성 성공과 사진 수정 성공은 각각 1회다. 목록 조회·저장·이름 변경·선택·삭제는 AI 호출이 아니다.
- 저장이나 목록 관리 실패는 생성된 이미지를 다시 생성하지 않고 재시도한다.
- 인물 생성 결과는 카드·사진 동기화와 독립적으로 유지한다.
- AI 사진 수정은 현재 카드 원본의 식별값을 확인하여 다른 원본에 오래된 결과를 적용하지 않는다.
- 인물 참고는 기존 subject 참조 계약을 사용하며, 원본은 image 0으로 유지한다.

## 검증

공급자 프롬프트·요청·인증·사용량 검사는 server/person-generation.test.mjs,
클라이언트 이미지 전송 검사는 server/photo-edit-api.test.mjs,
인물 저장 검사는 server/person-library.test.mjs에서 수행한다.
DB·스토리지 권한은 롤백 전용 SQL 검사로 검증한다. 브라우저에서는 생성→저장→
새로고침→인물 재선택→현재 카드 사진 수정→적용, 이름 변경·삭제, 저장 실패
재시도를 확인한다. 계정 격리는 저장 API 테스트와 DB 권한 검사로 확인하며,
브라우저의 로그인 계정 전환은 별도 실측하지 않았다. 공급자 성공 응답은 대체하며
유료 호출은 하지 않는다.
