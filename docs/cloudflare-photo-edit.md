# 대화형 사진 편집 서버

## 현재 운영 연결 — GPT Image 2 (2026-09-07)

Cloudflare Worker가 인증, 플랜 한도, 서비스 전체 하루 50회 제한을 검증한 뒤
OpenAI Images API를 호출한다. 현재 운영 공급자는 OpenAI이며, 사진 편집은
`/v1/images/edits`, 재사용 인물 생성은 `/v1/images/generations`를 사용한다.

- 모델 `gpt-image-2`, 품질 `medium`, 크기 `1024x1024`, 결과 1장.
- 출력 형식은 JPEG다.
- 편집 입력은 원본 사진을 `image[]`의 첫 항목으로 보내고, 참고 사진도 같은
  `image[]` 배열에 이어서 보낸다.
- 입력 사진은 브라우저에서 원본 비율을 유지한 긴 변 최대 1024px JPEG 사본으로
  준비한다. 원본 업로드/보관 파일은 축소하지 않는다.
- 참고 사진은 최대 3장이며, 각 사진도 JPEG와 가로·세로 1024px 이하를 검증한다.
- `OPENAI_API_KEY`는 Worker secret으로 보관하며 웹 빌드에 포함하지 않는다.
- Images API에만 연결한다. Chat/Responses/Files API를 호출하지 않는다.
- 원본 다음에 참고 사진을 보내고 용도를 명시한다. 인물 외형과 기존 소품의
  수량을 보존하도록 요청한다. 특정 인물 닮음은 보장하지 않는다.
- 실패 시 사용자 횟수는 환원하지만 전체 호출 상한에는 포함한다.
- API 호출은 입력·출력에 따라 과금된다. 자동 재시도나 다른 모델 대체는 없다.
- 클라이언트 대기 시간은 185초이며 서버 공급자 요청은 175초로 제한한다.

배포는 `wrangler deploy --config cloudflare/photo-edit/wrangler.jsonc`와
`npm run deploy:cloud`를 사용한다. 키 값은 CLI 인수, 출력, 공개 설정에 넣지
않는다. 공개 `/status`의 provider/model/quality/size와 로그인 후 실제 생성을
검증한다.

공식 계약: https://developers.openai.com/api/docs/guides/image-generation

통과했다. Pages 배포 `a88992f1`이며 운영 도메인이 새 `index-CnX5xJnu.js`를

차단한다.

운영 Chrome의 로그인된 웹에서 원본과 인물 참고 사진 1장을 보내 실제 생성에
성공했다. 출력 JPEG 1024×1024를 확인했고 컵은 한 개다. 변경안을 적용하지 않고
검토 상태로 남겼다. 검증은 배포 전에 열려 있던 탭에서 실행해 입력 준비는 기존
480px 경로를 사용했다. 새 1024px 입력 경로는 자동 테스트와 배포 번들로 확인했다.
이는 실제 연결 1회 검증이며 인물 유사도 성공률에 대한 반복 품질 평가는 아니다.
증거: `artifacts/openai-live-2026-09-07/generated.jpg`, `live-web.png`.

## 배포

1. Worker secret에 `OPENAI_API_KEY`를 설정한다. 웹 빌드나 `VITE_` 변수에는 넣지
   않는다.
2. Worker에 `SUPABASE_PUBLISHABLE_KEY`와 `PHOTO_EDIT_ENABLED=1`을 설정한다.
   Supabase service role 키는 사용하지 않는다.
3. `npx --yes wrangler@4.129.0 deploy --config cloudflare/photo-edit/wrangler.jsonc`
   실행.
4. 실제 `/status`, 로그인 없는 `/edit`, 로그인 후 실제 모델 결과를 확인한다.
5. `.env.production.local`에 실제 Worker 주소를 `VITE_PHOTO_EDIT_API_URL`로 설정한다.
6. 웹 테스트·빌드 후 `npm run deploy:cloud`로 배포하고 결과 적용·다운로드를
   검증한다.

## 품질 범위

사진 편집은 생성형 모델 결과이므로 컵, 상품, 손, 얼굴, 배경의 세부 형태가
달라질 수 있다. 변경안을 원본과 비교하고 적용해야 하며, 정확한 상품 형태 보존,
특정 실존 인물의 닮음, 모든 한국어 요청의 일관된 품질을 보장하지 않는다.

## 개인 사용량 제한 예외

- 운영자가 승인한 계정 UUID를 Worker의 `PHOTO_EDIT_UNLIMITED_USER_IDS` 설정으로 관리한다.
- 현재 예외 대상은 이창렬 회원 계정이다. 이름 변경이나 요청 본문으로 예외 권한을 얻을 수 없다.
- 개인 일/월 사용 횟수만 해제한다. 서비스 전체 하루 50회와 OpenAI 공급자 비용·한도는 계속 적용한다.
- 사용 기록 및 중복 요청 방지, 실패 시 처리도 유지한다. 결제 설정 변경은 하지 않는다.
- 이창렬 개인 한도 예외 배포: Worker `6086edbc-5c35-4931-b4d3-02b0d43d7d58`, 웹 `53038ad7`. 총87개 테스트 및 타입/빌드/클라우드 검사 통과.

## 인물 변경 지시 충돌 수정

기존에는 참고 사진 교체 요청에 한해서만 원본 인물 유지 규칙을 해제했다. 이제
명시적인 인물 추가·교체 요청 자체가 우선하며 참고 사진이 없어도 요청을 수행하도록
지시한다. 참고 사진 사용 시 얼굴/머리/외형을 기준으로 안내하고 UI는 인물·제품
참고로 표시한다. 성공 응답은 요청을 정확히 수행했다고 단정하지 않고 변경안을
만들었다고 알린다. 특정 실존 인물의 정확한 닮음은 검증하거나 보장하지 않는다.

88개 테스트와 빌드 검사 통과. Worker6fc8340e, Pages7ea0d51e. 공개 UI 참고 안내 확인.

## 얼굴 원본 유지 편집 (2026-09-07)

채팅의 **얼굴 원본 유지**를 켜고 편집 기준 사진과 보호 영역을 지정한다.
기준은 현재 카드 사진 또는 업로드한 참고 사진 중 하나다. 참고 사진을 고르면
그 사진 전체를 AI 편집의 기준으로 사용하고, 변경안을 현재 카드에 적용한다.
다른 사진의 얼굴을 자동으로 찾아 옮겨 붙이는 기능은 아니다.

사용 순서:

1. 원하는 인물의 사진을 참고 이미지로 추가한다.
2. 얼굴 원본 유지를 켜고 편집 기준 사진에서 해당 참고 사진을 선택한다.
3. 얼굴과 머리카락이 들어가도록 사진 위에서 사각형을 드래그한다.
4. 배경, 컵, 소품 등 보호 영역 바깥의 변경을 요청한다.
5. 변경안을 확인하고 이 사진 적용 → 보관함에 저장한다.

AI에는 기준 사진의 인물 위치·크기·각도·표정·구도를 유지하도록 지시한다.
응답 이미지를 기준 사진 크기에 맞춘 뒤, 브라우저에서 지정 영역의 원본 픽셀을
복원한다. 영역 바깥 2~16픽셀의 경계만 원본과 섞고, 내부는 다시 원본으로 덮어쓴다.
JPEG 재압축 없이 PNG로 내보내며 5MB 저장 제한을 넘으면 오류를 표시한다.
무손실 보존을 위해 자동 축소나 JPEG 전환을 하지 않는다.

보존 기준은 앱에서 불러온 사진의 디코딩된 픽셀이다. 최초 업로드 단계의 1600픽셀
축소 및 JPEG 변환보다 이전의 파일 바이트까지 보존한다는 뜻은 아니다.
얼굴의 각도·표정을 새로 만들거나 몸 자세를 크게 바꾸는 요청에는 제약이 있다.
AI가 머리나 몸의 위치를 이동시키면 경계나 주변 연결이 부자연스러울 수 있으므로
변경안을 확인해야 한다. 얼굴 자동 감지나 특정 인물 닮음 판정은 수행하지 않는다.

기준 사진·카드가 바뀌거나 기준 참고 사진을 제거하면 보호 영역을 초기화한다.
보호 모드에서 영역이 없으면 요청을 차단한다. AI 작업 중에는 기준과 영역을
바꿀 수 없다. 기존 적용/되돌리기와 계정별 한도, 서비스 전체 하루 50회 한도는
유지한다.

검증: 자동 테스트 94개, TypeScript, 빌드, 클라우드 검사 통과.
로컬 Chrome에서 실제 컴포넌트에 제어된 AI 응답을 연결해 드래그 선택 → Enter 요청 →
변경안 적용 후 픽셀을 비교했다. 240×320 PNG에서 보호 영역의 RGBA 차이는 0,
영역 밖 변경 픽셀은 58,168개였다. 되돌리기, 카드/기준 사진 전환 시 영역 초기화,
참고 사진을 편집 입력으로 사용하고 중복 첨부에서 제외하는 흐름도 확인했다.
검증 페이지는 `.omx/tests/photo-protection.html`이며 운영 빌드에는 포함하지 않는다.

운영 배포: Worker `e1aa26db-d1a0-4788-a28d-6b148a5d5e66`, Pages `8fbbbb81`.
공개 사이트의 얼굴 원본 유지 설정·영역 표시·기준 사진 로딩 및 이창렬 개인 제한
없음 표시를 확인했다. 이번 검증에서 실제 AI 호출이나 사용량 차감은 하지 않았다.
